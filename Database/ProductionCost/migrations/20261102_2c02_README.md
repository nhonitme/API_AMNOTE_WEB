## DDL đổi UNIQUE — khi nào chạy

| Tình huống | Hành động |
|------------|-----------|
| Cài **mới** từ `01_production_cost_tables.sql` / `2b_01_tables.sql` bản repo hiện tại | **Không chạy** DDL — schema đã đủ `POOL_DEPARTMENT_ID` + UNIQUE đầy đủ |
| DEV đã cài bảng 2B **cũ** (thiếu `POOL_DEPARTMENT_ID` hoặc UNIQUE cũ thiếu DEPT/POOL) | **Chạy** `20261102_2c02_ddl_alloc_detail_key.sql` trước `2c02_sp_alloc.sql` |
| Đã có cột + UNIQUE đúng | Script idempotent (ghi NOTE) — vẫn **không bắt buộc** |

Kiểm tra nhanh trước khi SOURCE:
```sql
SHOW COLUMNS FROM production_cost_alloc_detail LIKE 'POOL_DEPARTMENT_ID';
SHOW INDEX FROM production_cost_alloc_detail WHERE Key_name = 'uk_pc_alloc_detail';
-- Kỳ vọng UNIQUE: RUN_ID, RUN_VERSION, PRODUCT_ID, DEPARTMENT_ID, ACCOUNT_CD, POOL_DEPARTMENT_ID
```

## Quy tắc đã chốt

- B2 Confirm = `ALLOC_CONFIRMED` ≠ `CONFIRMED` toàn kỳ.
- B3 EXP chỉ nhận phân bổ đã khóa theo `RUN_ID+RUN_VERSION`.
- SP không `START/COMMIT` khi C# quản lý transaction.
- `load_pool` **không DELETE** khi `RUN.STATUS ∈ {ALLOC_CONFIRMED, CONFIRMED}` — không phụ thuộc STEP.
- UNIQUE: `(RUN_ID, RUN_VERSION, PRODUCT_ID, DEPARTMENT_ID, ACCOUNT_CD, POOL_DEPARTMENT_ID)`.
- JOIN theo `COMPANY_CD` + `*_ID` — không dùng `_CD` làm khóa liên kết.
- PeriodLock file canonical: migration `2b_04` **và** `Database/StoredProcedures/PeriodLock/CogsSummary/01_sp_period_lock_cogs.sql` đồng bộ.
